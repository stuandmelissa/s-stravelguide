# Park Intelligence Model

The app must recommend—not merely list.

## Priority classes
- `hero`: defining experience; protect first.
- `core`: normally included.
- `bonus`: add only with genuine slack; remove first when the day slips.
- `swap`: alternative stop, surfaced only when a primary stop fails (parking, closure, crowds).

## Ranking inputs
Route fit, scenic payoff, wildlife opportunity, photo value, time, walking effort, heat/altitude risk, parking friction, backtracking, energy, remaining daylight, and hotel ETA.

## Scores
Use 1–10 for scenic, photo, wildlife, crowd, parking risk, effort, and detour value. Scores must be editable data, not hard-coded UI logic.

## Integrity
Wildlife and parking are never guaranteed. Official alerts override cached content. Unknown values remain unknown. Never encourage illegal parking or unsafe roadside stopping.
